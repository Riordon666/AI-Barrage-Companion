# AI Barrage Companion（ABC）项目策划书

## 一、项目定位

AI Barrage Companion（ABC）是一款桌面端虚拟弹幕陪伴应用。它通过轻量分析用户当前屏幕状态，调用用户配置的大模型生成类似直播间观众的弹幕，并以透明悬浮层形式显示在屏幕上。

产品核心不是精准识别画面内容，而是根据屏幕节奏和用户状态，模拟“有人在看、有人在吐槽、有人在鼓励”的环境反馈。

## 二、目标用户

目标用户包括：

- 想要直播氛围但不方便真实开播的用户
- 独自打游戏、学习、写代码、剪视频时希望获得陪伴感的用户
- 喜欢弹幕文化、吐槽文化、虚拟观众互动的用户

典型场景：

- 用户打游戏时，屏幕上出现“这波可以”“别急别急”“前面的别奶”
- 用户写代码卡住时，弹幕出现“又报错了是吧”“稳住，快好了”
- 用户长时间无操作时，弹幕出现“主播挂机了？”“人呢人呢”

## 三、核心价值

ABC 要解决的问题是：普通 AI 助手是对话工具，需要用户主动提问；而 ABC 是环境反馈系统，可以主动根据用户状态生成氛围反馈。

产品价值可以概括为：

> 把 AI 从“聊天框里的助手”变成“屏幕上的虚拟观众”。

## 四、MVP 功能设计

第一版目标是跑通最小闭环，不追求复杂识别。

MVP 必须实现：

1. 屏幕状态采集

   使用 `mss` 定时截图，但不上传截图，只在本地计算画面变化率、静止时间、重复度等基础指标。

2. 场景摘要生成

   本地生成粗粒度 `scene summary`，例如：

   ```json
   {
     "pace": "fast",
     "activity": "active",
     "event": "normal",
     "duration_static": 2
   }
   ```

3. AI 弹幕生成

   用户配置 API Key、Base URL、Model。每 4 秒左右请求一次大模型，生成 3 条短弹幕。

4. 弹幕显示

   使用 PySide6 创建透明置顶窗口，弹幕从右向左移动，多轨道显示，避免重叠。

5. 基础控制

   支持暂停/继续、弹幕密度低/中/高、退出应用。

6. 基础人格

   第一版内置 5 类人格：吐槽、鼓励、阴阳、跟风、乐子人。MVP 只做随机混合，不做复杂人格管理。

## 五、非 MVP 功能

第二阶段再实现：

- 用户输入弹幕
- 点击弹幕禁言某类人格
- 黑名单和白名单
- 弹幕引用前文
- 缓存弹幕池
- 成本模式切换：沉浸、平衡、省电

第三阶段再实现：

- 自动节流
- 困难状态检测
- 游戏专项适配
- 教练型人格
- 长期上下文记忆

## 六、技术方案

整体流程：

```text
屏幕截图
→ 本地画面变化分析
→ 生成 scene summary
→ 调用大模型
→ 解析弹幕 JSON
→ 弹幕调度
→ 透明窗口渲染
```

建议目录结构：

```text
core/
  screen_capture.py
  frame_analyzer.py
  ai_service.py
  barrage_manager.py

ui/
  overlay.py
  control_panel.py

config/
  settings.py
```

关键模块：

- `ScreenCapture`：周期截图，只提供图像给本地分析模块
- `FrameAnalyzer`：计算变化率、静止时间、重复度，生成场景摘要
- `AIService`：兼容 OpenAI 格式接口，支持 DeepSeek、OpenAI 或其他兼容模型
- `BarrageManager`：负责去重、限流、轨道分配、节奏控制
- `OverlayRenderer`：负责透明窗口、弹幕动画、显示层级

## 七、AI 设计

基础 Prompt：

```text
你是直播间观众，请根据当前场景生成弹幕。

要求：
- 每条 10 个字以内
- 像真人观众
- 有情绪
- 不要解释
- 不要输出脏话、人身攻击、隐私内容

场景：
{scene_summary}

输出 JSON 数组，包含 3 条弹幕。
```

输出示例：

```json
[
  {"persona": "troll", "text": "这波有点慌"},
  {"persona": "support", "text": "稳住能赢"},
  {"persona": "follower", "text": "前面的对"}
]
```

人格定义：

- `troll`：轻度吐槽，不做人身攻击
- `support`：鼓励、安慰、稳住气氛
- `sarcastic`：轻微阴阳怪气，但不过界
- `follower`：跟风、复读、认同前面弹幕
- `fun`：玩梗、看热闹、制造直播间感

## 八、成本控制

默认使用“平衡模式”：

- 普通状态：4 秒一次 AI 请求
- 低变化状态：降低到 8 到 12 秒一次
- 高变化状态：立即触发一次生成
- 重复场景：优先使用缓存弹幕池

成本按公式估算：

```text
每小时成本 =
每小时调用次数 × 单次输入 tokens × 输入单价
+ 每小时调用次数 × 单次输出 tokens × 输出单价
```

按 DeepSeek 官方模型价格页，`deepseek-v4-flash` 当前中文价格为：缓存命中输入 0.02 元 / 百万 tokens，缓存未命中输入 1 元 / 百万 tokens，输出 2 元 / 百万 tokens。产品价格可能变化，最终应以官方页面为准：[DeepSeek 模型 & 价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

## 九、隐私与安全

隐私原则：

- 不上传截图
- 不保存截图
- 不做 OCR 读取文字
- API 请求只发送粗粒度场景摘要
- 用户可随时暂停
- 后续版本提供应用黑名单，例如密码管理器、聊天软件、银行页面自动暂停

第一版必须避免把窗口标题、屏幕文字、文件名直接发送给模型。

## 十、验收标准

MVP 完成标准：

- 软件启动后出现透明弹幕层
- 弹幕能从右向左平滑滚动
- 弹幕不会明显重叠
- 用户可以暂停、继续、调节密度
- 不上传截图，只上传场景摘要
- API 配置错误时有明确提示
- 无 API Key 时可以使用本地模拟弹幕运行演示

## 十一、开发计划

第一阶段：最小可运行版本，预计 1 到 3 天。

- 项目结构搭建
- 截屏与画面变化分析
- 透明弹幕窗口
- 模拟弹幕滚动

第二阶段：AI 接入，预计 2 到 4 天。

- API 配置
- Prompt 设计
- JSON 解析
- 失败重试和降级弹幕

第三阶段：体验增强，预计 3 到 7 天。

- 人格权重
- 弹幕缓存池
- 密度调节
- 简单黑名单

## 十三、文档存放规范

## 十四、一句话总结

AI Barrage Companion 是一个 AI 驱动的虚拟观众系统，用轻量屏幕状态分析和弹幕式反馈，为用户创造“被观看、被吐槽、被陪伴”的沉浸体验。
